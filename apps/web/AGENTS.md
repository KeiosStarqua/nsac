# apps/web

## Purpose

Web app for **Sky**, the clinical assistant for astronauts and flight surgeons. Routes: `/` — the SKY HUD (1672×941 astronaut wellness interface from `SKY_UI_COMPONENT_FUNCTIONAL_SPEC.md`: SkyIdentity, MissionContext, VitalsProjection, AICoreOrb, ConversationLens, HealthProjection, OrganicInputSurface, MicrophoneOrb + one authoritative voice-phase state machine, fixture ‘Simulated data’, canvas/SVG only) with the astronaut picker (`features/astronaut/`, picked id saved in localStorage `nsac.astronaut`, claim-locked through the backend `/api/claims` with an anonymous session in localStorage `nsac.session` — one session holds one crew member, unreachable backend ⇒ local pick still works and claims are simply not enforced; picker shown before the HUD on first visit) and the React Bits Crystalized Ball in the orb zone; `/watch` — the smartwatch mockup frame with the live Watch HUD clipped in the glass face (`features/sky-hud/watch-device.css` + the AI-generated mockup PNG, every viewport, phone included) with a floating Console | Watch chip top-right (hidden ≤480px); `/data` — the standalone nsac-data map served as a complete HTML document via a server route (`routes/data.ts`, `server.handlers.GET`) with no app chrome, no React, no three.js. The bytes are read from disk per request by `features/data/data.server.ts` straight from the `data` submodule (`data/DATA.html`) — do not copy the file into this package; `/body` — the Open Anatomy 3D body map (`features/body-map/`, full-page route rendering the fullscreen `variant="page"` — canvas + floating "Body systems" rail + one attribution line, no header/footer/back link, Escape → HUD; the HUD overlay `variant="overlay"` is untouched; three.js loaded only there, CC BY 4.0 attribution); `/health` — agent configuration readiness + roster, no secrets; `/spacecraft` — full-screen cinematic NASA ISS viewer (`features/spacecraft/`, full-page route, lazy three.js scene, streaming data path by default — the ISS-B overview paints first then the full-detail station streams in around the camera and crossfades in (`features/iss/`); `?stream=0` keeps the one-shot full-detail GLB; draco decoder served locally from `public/draco/`, no simulation, no UI chrome); `/admin` — hidden operator page (not in nav, `noindex,nofollow`) to switch the model Sky's agent uses at runtime: requires `SKY_ADMIN_KEY` set on the box (without it the page shows "admin not configured" and every admin function refuses) and a signed `sky_admin` session cookie (HMAC-SHA256, 30 min); the model id must match the live OpenRouter `/api/v1/models` catalog and is stored in backend SQLite (`app_settings`, `agent.model`) via `PUT /api/settings/agent-model`; agent resolution order is backend setting → `SKY_OPENROUTER_MODEL` → hardcoded default. The HUD's hologram button links to `/body`; a small chrome nav chip in the HUD header (top-right, next to the mission trigger, hidden in Watch Mode ≤480px) links to `/spacecraft`; three.js never loads on `/`. It is a showcase, not the astronaut's app (that is `apps/onboard`, NiceGUI).

- Add a Sky station: add the id to `STATION_IDS` and `STATION_FACTS` in `shared/sky.ts`, add `name`, `brief` and a digit-free `preset` to both locales, place `<SkyStation id>` in the route (`headingLevel="one"` only when the panel's title is the page title, as on `/`). A new fact needs `FACT_IDS`, `FACT_META` (with a source) and a value in both locales.
- Add a catalog component: vendor the Arc component under `src/components/arc/<name>/` (MIT, keep the uiarc.dev attribution in the catalog comment), wrap it with `defineComponent` in `catalog/library.tsx` (zod props, no state-changing action, free text through `safeText`), register it in `skyLibrary` — and in `Card`'s `children` union if it nests in a card — and cover it in `catalog/library.test.ts`.
- Keep pure logic (`model/`) free of React and IO so `vitest` can cover it. `vitest.config.ts` is separate from `vite.config.ts` on purpose (no Start/Nitro plugins in tests).
- `src/routeTree.gen.ts` is generated and gitignored.
