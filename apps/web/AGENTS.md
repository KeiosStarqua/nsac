# apps/web

## Purpose

Web app for **Sky**, the clinical assistant for astronauts and flight surgeons. Routes: `/` (the SKY HUD — the 1672×941 astronaut wellness interface from `SKY_UI_COMPONENT_FUNCTIONAL_SPEC.md`: SkyIdentity, MissionContext, VitalsProjection, AICoreOrb, ConversationLens, HealthProjection, OrganicInputSurface, MicrophoneOrb + one authoritative voice-phase state machine, fixture ‘Simulated data’, canvas/SVG only), `/console` (the former homepage: Sky's console — exactly one image, OpenUI-composed by the PI SDK agent), `/concept` (the product description: hero, the two core features, five hazards, data and standards, the detect → recommend → confirm → report loop, demo teaser, story teaser, modules, safety rules, sources), `/demo` (interactive Mars landing readiness), `/sky` (the living interface: Living Core canvas, the §4 state machine, OpenUI-style scene IR, 12 device embodiments, simulated mission data — all deterministic, no network needed), `/story` (the "Sky" story). It is a showcase, not the astronaut's app (that is `apps/onboard`, NiceGUI). On every page Sky (a static angel image) flies over the interface and, at each station it lands on, composes a panel with OpenUI.

## Ownership

- Owns everything under `apps/web/`. The root `package.json`, `turbo.json` and `tsconfig.base.json` belong to the root `AGENTS.md`.
- Concept content comes from the team PRD, `NASA HACKATHON_Prd Description.pdf` at the repo root (local only, `*.pdf` is gitignored): objective, the two core features with their onboarding examples, the five hazards with symptom risks and measurement tools, and the data table. Keep the page in step with it.
- `STORY.md` at the repo root is the only source of the story text. This app renders it; never copy it into `src/`. Edit the story in `STORY.md`.
- `practice/` is separate. Nothing here is copied from it.

## Local Contracts

- Stack: TanStack Start (Vite) + TanStack Router file routes, React 19, Nitro, zod, react-markdown, OpenUI (`@openuidev/react-lang`, pinned), `@earendil-works/pi-coding-agent` (pinned 1.5.2, MIT — verified 2026-11-11; runs the composer server-side, lazy imported), motion, lucide-react and `@radix-ui/react-dialog` (the last three come with the Arc components; licences MIT, ISC, MIT — verified in `apps/web/node_modules/*/package.json`, 2026-11-10). Bun is the package manager; run from the repo root (`bun install`) or this folder. Every dependency must be OSI-approved.
- OpenUI catalog (`features/sky-guide/catalog/library.tsx`): root component `Console`, then `Card`, `Say`, `Fact`, `Badge`, `Alert`, `Steps`, `GoTo`. Each wraps an Arc component from https://uiarc.dev (MIT, checked 2026-11-10), vendored under `src/components/arc/` (`alert`, `badge`, `button`, `card`, `gauge`, `stepper`, `text-reveal`; no LICENSE file in the folder — origin and licence live in the `library.tsx` and `global.css` comments). Sky's rules hold: no state-changing action, digits only through `Fact(id)`, no digit in free text.
- Tokens: Arc's design tokens live in `src/components/arc/foundation.css`, loaded as its own stylesheet from `src/routes/__root.tsx` before the app stylesheet. `src/styles/global.css` maps them onto Sky's dark palette under `:root[data-theme="dark"]` (`<html>` carries `data-theme="dark"`, set in `__root.tsx`). One token layer: `--surface`, `--border`, `--accent`, `--text-*`, `--radius-*`, `--space-*`, `--ease-*`, `--duration-*`, `--shadow-*`, `--font-display`/`--font-body`.
- Runtime: the application model does not depend on the runtime. Only `nitro({ preset })` in `vite.config.ts` selects it: `bun` by default, `NITRO_PRESET=node-server` for Node.
- Offline: no CDN fonts, scripts, images or API calls — the page must render with the network unplugged. Composing panels additionally needs the network and a saved OpenRouter key; without them the presets stay (that is the designed fallback, not an error).
- Layout: `src/routes/` (thin, file-based) → `src/features/<name>/` (`index.ts` is the public surface) → `src/shared/` (never imports features). Feature code may import `shared/`; routes compose features.
- Server boundary: `*.server.ts` is server-only and starts with `import "@tanstack/react-start/server-only"`. It is imported only by the matching `*.functions.ts` (`createServerFn`). Routes and components call the `*.functions.ts` exports. Do not read `process.env` or the file system outside these files.
- Search params are validated with zod and are lenient: a bad value falls back (`.optional().catch(undefined)`) and never shows an error page. `?lang=en|vi` lives on the root route; `?stage=` on `/demo`. Language comes from `?lang=`, then `Accept-Language` (server function `getRequestLocale`).
- SSR mode per route, with the reason in the route file: `/`, `/concept` and `/story` `ssr: true` (content); `/demo` `ssr: 'data-only'` (loader on the server, interactive client component). `/concept` defers the demo-teaser snapshot with `Await` (streaming); `/demo` fast-forward streams one `Snapshot` per day from an async-generator server function.
- Content: all UI text is in `src/shared/i18n/{en,vi}.ts` against one `Copy` type, so the two languages cannot drift. The story text stays Vietnamese (it is `STORY.md`).
- PRD thresholds: the PRD's hazard tables carry numeric limits (e.g. pulse wave velocity, troponin, ONSD) with no source URL, so the page does not show them. Only limits that trace to NASA-STD-3001 Vol. 1 Rev B are shown, each linked to its `[V1 xxxx]` requirement. The PRD also calls Sky a model trained and fine-tuned on NASA data; the page does not claim that, because the implementation is deterministic detection plus a local model with retrieval over NASA documents (root `AGENTS.md`).
- Claims: every outbound claim links to an entry in `src/shared/sources.ts`, with `checked` only when a person opened the URL. Demo numbers are illustrative and labelled "Simulated data". Do not add medical thresholds or weights here. Keep the disclaimer "AI-generated, not a substitute for a physician".
- No personal data, no photos or images of minors.
- Demo rule: nothing is queued or sent before Confirm (`canConfirm` / `canFastForward` / `linkStateFor` in `features/readiness-demo/model/readiness.ts`).
- Sky guide (`features/sky-guide`): `SkyGuideProvider` in the root layout hosts the flying Sky; routes place `<SkyStation id>` (ids in `shared/sky.ts`; `console` is the station on `/`, the others sit on `/concept`, `/demo` and `/story`). Sky flies to the station nearest the reading line; Clicking Sky opens the Ask Sky panel (`components/SkyAsk.tsx`): the viewer types one instruction (280 chars max) and the composer re-composes the panel Sky is on with it folded into the PI SDK prompt (`ask` rides `ComposeInput` → `composeStation`; the system prompt is unchanged and `reviewProgram` still gates the answer). The asked-for panel bypasses the `station:locale` cache and is never written to it. The guided tour is a separate fixed text button in `SkyCompanion.tsx`; Sky's click no longer toggles the tour. Each station passes a panel scope to the catalog: `PanelScopeProvider` (`catalog/library.tsx`) wraps the panel with the station's allowed facts (`STATION_FACTS[id]`) and the heading level of the panel title (`one` when the panel is the page, as on `/`; `two` inside a page that has its own title). On arrival the station renders its built-in OpenUI Lang preset (`copy.sky.stations[id].preset`) at once, then composes a panel through the PI SDK (`@earendil-works/pi-coding-agent`, lazy import like the kirector agent) with an OpenRouter model — `SKY_OPENROUTER_MODEL`, default `anthropic/claude-sonnet-4.5`; `SKY_OPENROUTER_BASE_URL` points at an OpenAI-compatible `/v1` base for smoke tests; the server-only env read lives in `api/compose.server.ts`. With no key saved, no network, or a failed turn the preset stays. The key, in order: the `SKY_OPENROUTER_API_KEY` environment variable (preferred for the deployed demo — set through the service environment, never in the repo or flake; malformed counts as unset), then one key per machine in `var/sky-openrouter.json` under the process cwd (mode 0600, gitignored; override with `NSAC_SETTINGS_PATH`), kept write-only by `api/key.server.ts` — no read path returns it, `api/key.functions.ts` exposes only the write-only `saveOpenRouterKeyFn` (validate, store). When `composeStation` yields `missing_key`, the station opens `OpenRouterKeyDialog` (Radix chrome; the panel inside is OpenUI Lang built by `model/key-panel.ts` and rendered with `catalog/key-panel.tsx` — `keyPanelLibrary`, the one extension of `skyLibrary`, adding `KeyField`, `SaveKeyButton` and the custom `SaveOpenRouterKey` action, which only this hand-written panel uses). Saving bumps `keyVersion` in the SkyGuide context and every unsettled station composes again. A settled panel with `origin: "offline"` shows a footer link to set or replace the key. There is no read path for the key; the only server surface is the write-only `saveOpenRouterKeyFn`.
- Sky panel safety: the model-facing OpenUI catalog (`catalog/library.tsx`) has no actions — the key panel's components and its one custom action live in the separate `catalog/key-panel.tsx` extension and are never offered to a model. Numbers reach a panel only through `Fact(id)`; values come from `copy.sky.facts`, sources from `FACT_META`, and the panel scope limits facts to `STATION_FACTS[id]` (a disallowed `Fact` is dropped while streaming and rejected on review). `reviewProgram` rejects a model panel that does not parse cleanly, writes a digit in free text, or uses a fact the station does not allow, and the preset is shown instead. Presets pass the same review (tested); the key panel program parses cleanly (tested). NASA-STD-3001 facts must equal the `data.rows` value with the same requirement (tested). The OpenRouter key never reaches the browser except as the form state of the hand-written key panel, and is only ever sent to the server's write-only store.
- Sky artwork: `SKY_IMAGE` in `features/sky-guide/components/SkyCompanion.tsx`, currently the placeholder `public/sky/angel.svg`. The final art is a static image with a transparent background, square, of an adult or abstract figure (no child-like cherub, root rule 5). It is AI-generated (Cursor), so list it in the AI disclosure and record its tool and terms before submission.
- OpenUI telemetry: runtime telemetry is opt-in and off; install telemetry is a postinstall script that bun does not run. Install with `DO_NOT_TRACK=1` and do not add `@openuidev/*` to `trustedDependencies`.

## Work Guidance

- Add a page: create `src/routes/<name>.tsx`, put the UI in a feature, add copy to both locales, add a nav link in `shared/layout/Header.tsx`, state the SSR mode and why, and place at least one `<SkyStation>`.
- Add a Sky station: add the id to `STATION_IDS` and `STATION_FACTS` in `shared/sky.ts`, add `name`, `brief` and a digit-free `preset` to both locales, place `<SkyStation id>` in the route (`headingLevel="one"` only when the panel's title is the page title, as on `/`). A new fact needs `FACT_IDS`, `FACT_META` (with a source) and a value in both locales.
- Add a catalog component: vendor the Arc component under `src/components/arc/<name>/` (MIT, keep the uiarc.dev attribution in the catalog comment), wrap it with `defineComponent` in `catalog/library.tsx` (zod props, no state-changing action, free text through `safeText`), register it in `skyLibrary` — and in `Card`'s `children` union if it nests in a card — and cover it in `catalog/library.test.ts`.
- Keep pure logic (`model/`) free of React and IO so `vitest` can cover it. `vitest.config.ts` is separate from `vite.config.ts` on purpose (no Start/Nitro plugins in tests).
- `src/routeTree.gen.ts` is generated and gitignored.

## Verification

From the repo root: `bun run typecheck`, `bun run test`, `bun run build` (Turborepo runs this package). Production: `PORT=3100 bun run .output/server/index.mjs` from `apps/web` after a build. Check by hand: `/` console — exactly one image (Sky), the panel title is the page's `h1`, and with a key saved and network up the cards are model-composed (the preset shows only while composing or when the model is unavailable); with no key saved the dialog asks for it; `/?lang=vi`; `/concept`, `/story`, `/demo` (Confirm, then Fast-forward); Sky landing on each station and the click-to-tour; network unplugged (the page and the presets still render — only composing needs the key and the network). To check the model path without a real OpenRouter key, run a local mock that streams OpenAI-compatible `/v1/chat/completions` SSE and point `SKY_OPENROUTER_BASE_URL` at it with `NSAC_SETTINGS_PATH` at a saved fake key — verified 2026-11-11 to yield `chunk` events and `end`. The real OpenRouter path has not been run from this machine (no key saved); the demo laptop needs `var/sky-openrouter.json` or a key entered in the dialog.
