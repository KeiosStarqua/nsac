# apps/web

## Purpose

Web app for **Sky**, the clinical assistant for astronauts and flight surgeons. Routes: `/` — the **"SKY · Astronaut Wellness" mock console** (`features/hud-mock/`, default since 2026-11-15: three-column simulated dashboard — astronaut profile + vital signs + quick trends / orb + greeting + voice / overall readiness with four detail tabs + three mini metric cards + one deterministic insight band to `/performance`; see its own bullet below) with the astronaut picker (`features/astronaut/`, picked id saved in localStorage `nsac.astronaut`, claim-locked through the backend `/api/claims` with an anonymous session in localStorage `nsac.session` — one session holds one crew member, unreachable backend ⇒ local pick still works and claims are simply not enforced; claims tự giải phóng sau 30 phút idle (heartbeat mỗi 30 s khi tab visible qua `useClaimHeartbeat` + `POST /api/claims/heartbeat`; sweep lười trong `list`/`claim`/`heartbeat` + interval 60 s backend, `SKY_CLAIM_TTL_MINUTES` override); mở lại claim còn trống → tự re-claim im lặng, còn bị session khác giữ → mở picker; picker có nút **force release** (chỉ hiện khi ≥1 crew bị người khác giữ, 2 bước confirm inline trong `AstronautPicker` → `releaseAllClaims` → `POST /api/claims/reset`, unauthenticated theo demo contract) và backend bump `claims.reset.epoch` trong `app_settings`; mọi tab đang mở poll claims mỗi 45 s khi visible (`useClaimsWatcher`) + lúc mount, epoch lệch `localStorage["nsac.claims_epoch"]` → bỏ `nsac.astronaut` và về picker (kick thật cho tab đang mở; `/watch` và `/spacecraft` không wire watcher); picker shown before the HUD on first visit; every card's circle is the crew member's portrait from `public/astronauts/<id>.png`, with the old initials as the on-error fallback) and the React Bits Crystalized Ball in the orb zone; `/watch` — the smartwatch mockup frame with the live Watch HUD clipped in the glass face (`features/sky-hud/watch-device.css` + the AI-generated mockup PNG, every viewport, phone included) with a floating Console | Watch chip top-right (hidden ≤480px); `/data` — the standalone nsac-data map served as a complete HTML document via a server route (`routes/data.ts`, `server.handlers.GET`) with no app chrome, no React, no three.js. The bytes are read from disk per request by `features/data/data.server.ts` straight from the `data` submodule (`data/DATA.html`) — do not copy the file into this package; `/performance` — SKY / Human Performance, the fitness-style 12-metric demo face (`features/performance/`, simulated tiles + a deterministic one-line insight, the followed crew member's portrait in the header, backend `/api/health/performance/:id` with a fixture fallback); `/research` — SKY / Research Evidence, a read-only view of the NASA analog cohort research datasets behind the demo (`features/research/`; analog research — never the fictional crew; not medical advice); `/body` — the Open Anatomy 3D body map (`features/body-map/`, full-page route rendering the fullscreen `variant="page"` — canvas + floating "Body systems" rail + one attribution line, no header/footer/back link, hover/tap a structure → a tooltip of its catalog facts (name, system, category) at the pointer, Escape → HUD; the HUD overlay `variant="overlay"` is untouched; three.js loaded only there, CC BY 4.0 attribution); `/health` — agent configuration readiness (provider + source, key of the selected provider, effective model per profile) + roster, no secrets; `/spacecraft` — full-screen cinematic NASA ISS viewer (`features/spacecraft/`, full-page route, lazy three.js scene, streaming data path by default — the ISS-B overview paints first then the full-detail station streams in around the camera and crossfades in (`features/iss/`); `?stream=0` keeps the one-shot full-detail GLB; draco decoder served locally from `public/draco/`, no simulation, one piece of chrome only — the crew presence avatar group in the bottom-left (`components/CrewPresence.tsx` + the beui-adapted `src/shared/beui/avatar-group.tsx`, MIT, showing which fictional crew member is checked in, as their portraits), plus a simulated crew-position layer on the 3D model (`model/crew-positions.ts` fixture: six fictional crew, world-space anchors near Unity/Destiny, MBS-Robotics, Zvezda, Columbus, Kibo and Cupola, sinusoidal micro-drift ±0.5 m, static under reduced motion; `scene/CrewMarkers.tsx` emissive dots + runtime-canvas portrait sprites with an initials fallback, , depthTest=false, colours mirror presence) and a static `POSITIONS SIMULATED` caption line (never telemetry, no names/modules in the DOM)); `/admin` — hidden operator page (not in nav, `noindex,nofollow`) to switch the provider and models Sky's agent uses at runtime: requires `SKY_ADMIN_KEY` set on the box (without it the page shows "admin not configured" and every admin function refuses) and a signed `sky_admin` session cookie (HMAC-SHA256, 30 min); a Provider dropdown (OpenCode Go `opencode-go` — default | OpenRouter `openrouter` — legacy), a "Default (all agents)" dropdown and four per-profile dropdowns (`sky-chat` Chat, `sky-orchestrator` Orchestrator, `sky-generative-ui` Generative UI, `sky-hud-composer` HUD Composer — en/vi labels with one-line hints; per-profile "Use default" keeps the inherited model); the OpenCode Go option reads a committed static snapshot of the SDK's `opencode-go` catalog (`features/admin/model/goCatalog.ts`, regenerate with `bun apps/web/scripts/sync-go-catalog.mjs` after an SDK bump; free tier excluded — external clients get HTTP 403) while the OpenRouter branch reuses one live `/api/v1/models` fetch; Apply calls `setAgentConfigFn` → `PUT /api/settings/agent-models` (backend writes `agent.provider` / legacy `agent.model` / `agent.models` in one transaction; the legacy `PUT /api/settings/agent-model` route is kept for back-compat and for the box to run against either web version); agent resolution order is backend `agent.models[profile]` → backend `agent.model` → `SKY_AGENT_MODEL` → provider-specific env (`SKY_OPENCODE_MODEL` / `SKY_OPENROUTER_MODEL`) → provider default (`opencode-go` → `deepseek-v4.1-flash`, `openrouter` → `thinkingmachines/inkling-2-small:free`); a second panel clears every astronaut claim for demo housekeeping through `resetClaimsFn` → `POST /api/claims/reset` (backend endpoint carries no auth by design and is loopback-only, so the admin cookie is the only gate; the backend body is never echoed and the page does not refresh the roster afterwards). The HUD's hologram button links to `/body`; a small chrome nav chip in the HUD header (top-right, next to the mission trigger, hidden in Watch Mode ≤480px) links to `/spacecraft`; three.js never loads on `/`. It is a showcase, not the astronaut's app (that is `apps/onboard`, NiceGUI).

## Ownership

- Owns everything under `apps/web/`. The root `package.json`, `turbo.json` and `tsconfig.base.json` belong to the root `AGENTS.md`.
- Concept content comes from the team PRD, `NASA HACKATHON_Prd Description.pdf` at the repo root (local only, `*.pdf` is gitignored): objective, the two core features with their onboarding examples, the five hazards with symptom risks and measurement tools, and the data table. Keep the page in step with it.
- `STORY.md` at the repo root is the only source of the story text. This app renders it; never copy it into `src/`. Edit the story in `STORY.md`.
- `practice/` is separate. Nothing here is copied from it.
