# apps/web

## Purpose

Web app for **Sky**, the clinical assistant for astronauts and flight surgeons. Routes: `/` — the **"SKY · Astronaut Wellness" mock console** (`features/hud-mock/`, default since 2026-11-15: three-column simulated dashboard — astronaut profile + vital signs + quick trends / orb + greeting + voice / overall readiness with four detail tabs + three mini metric cards + one deterministic insight band to `/performance`; see its own bullet below) with the astronaut picker (`features/astronaut/`, picked id saved in localStorage `nsac.astronaut`, claim-locked through the backend `/api/claims` with an anonymous session in localStorage `nsac.session` — one session holds one crew member, unreachable backend ⇒ local pick still works and claims are simply not enforced; claims tự giải phóng sau 30 phút idle (heartbeat mỗi 30 s khi tab visible qua `useClaimHeartbeat` + `POST /api/claims/heartbeat`; sweep lười trong `list`/`claim`/`heartbeat` + interval 60 s backend, `SKY_CLAIM_TTL_MINUTES` override); mở lại claim còn trống → tự re-claim im lặng, còn bị session khác giữ → mở picker; picker có nút **force release** (chỉ hiện khi ≥1 crew bị người khác giữ, 2 bước confirm inline trong `AstronautPicker` → `releaseAllClaims` → `POST /api/claims/reset`, unauthenticated theo demo contract) và backend bump `claims.reset.epoch` trong `app_settings`; mọi tab đang mở poll claims mỗi 45 s khi visible (`useClaimsWatcher`) + lúc mount, epoch lệch `localStorage["nsac.claims_epoch"]` → bỏ `nsac.astronaut` và về picker (kick thật cho tab đang mở; `/watch` và `/spacecraft` không wire watcher); picker shown before the HUD on first visit; every card's circle is the crew member's portrait from `public/astronauts/<id>.png`, with the old initials as the on-error fallback) and the React Bits Crystalized Ball in the orb zone; `/watch` — the smartwatch mockup frame with the live Watch HUD clipped in the glass face (`features/sky-hud/watch-device.css` + the AI-generated mockup PNG, every viewport, phone included) with a floating Console | Watch chip top-right (hidden ≤480px); `/data` — the standalone nsac-data map served as a complete HTML document via a server route (`routes/data.ts`, `server.handlers.GET`) with no app chrome, no React, no three.js. The bytes are read from disk per request by `features/data/data.server.ts` straight from the `data` submodule (`data/DATA.html`) — do not copy the file into this package; `/performance` — SKY / Human Performance, the fitness-style 12-metric demo face (`features/performance/`, simulated tiles + a deterministic one-line insight, the followed crew member's portrait in the header, backend `/api/health/performance/:id` with a fixture fallback); `/research` — SKY / Research Evidence, a read-only view of the NASA analog cohort research datasets behind the demo (`features/research/`; analog research — never the fictional crew; not medical advice); `/body` — the Open Anatomy 3D body map (`features/body-map/`, full-page route rendering the fullscreen `variant="page"` — `role="img"` canvas + floating "Body systems" rail + one attribution line, one Esc·HUD kbd chip (Escape's twin → HUD), an accessible Body Tree (left-edge toggle; keyboard/SR list grouped by system) and a non-drag view-controls pill (`top-[12px]` centered — rotate / zoom / Reset View), no other chrome, hover/tap a structure → a tooltip of its catalog facts (name, system, category) at the pointer, Escape closes the tree drawer first, then → HUD; the HUD overlay `variant="overlay"` is untouched; three.js loaded only there, CC BY 4.0 attribution); `/health` — agent configuration readiness (provider + source, key of the selected provider, effective model per profile) + roster, no secrets; `/spacecraft` — full-screen cinematic NASA ISS viewer (`features/spacecraft/`, full-page route, lazy three.js scene, streaming data path by default — the ISS-B overview paints first then the full-detail station streams in around the camera and crossfades in (`features/iss/`); `?stream=0` keeps the one-shot full-detail GLB; draco decoder served locally from `public/draco/`, no simulation, one piece of chrome only — the crew presence avatar group in the bottom-left (`components/CrewPresence.tsx` + the beui-adapted `src/shared/beui/avatar-group.tsx`, MIT, showing which fictional crew member is checked in, as their portraits), plus a simulated crew-position layer on the 3D model (`model/crew-positions.ts` fixture: six fictional crew patrolling closed 3-waypoint loops through the connected modules — Unity/Destiny → Harmony, MBS, Zvezda, Columbus → Harmony, Kibo → Harmony, Tranquility/Cupola — at walking pace with a standing pause at each waypoint (`phase: walk|hold`), static under reduced motion; `scene/CrewMarkers.tsx` emissive dots + runtime-canvas portrait sprites with an initials fallback, , depthTest=false, colours mirror presence) and a static `POSITIONS SIMULATED` caption line (never telemetry, no names/modules in the DOM)); `/admin` — hidden operator page (not in nav, `noindex,nofollow`; `/admin` redirects to `/admin/models`, and each of the five tabs has its own route — `/admin/models` (default), `/admin/keys`, `/admin/speech`, `/admin/claims`, `/admin/background` — so they can be linked directly; `/admin/opencode` and `/admin/elevenlabs` are 307 redirects to `/admin/keys` kept for old deep links; the beui MorphingTabs tab bar is driven by the route and clicking a tab is a real navigation; ≤480px the rail swaps for a labeled `<select>` section picker (`useMediaQuery("(max-width: 480px)")`) because the rail can only fit icon-only tabs there), laid out as five tabs (Agent models | API Keys | Speech Engine | Reset claims | Background) with the beui-adapted Morphing Tabs in `src/shared/beui/morphing-tabs.tsx` (controlled by the route — `value` from `useRouterState` pathname mapped through `features/admin/model/admin-tabs.ts`, `onValueChange` → `useNavigate`; apply-time validation unchanged — server rejects non-catalog ids with `invalid_model`), a "Default (all agents)" dropdown and four per-profile dropdowns (`sky-chat` Chat, `sky-orchestrator` Orchestrator, `sky-generative-ui` Generative UI, `sky-hud-composer` HUD Composer — en/vi labels with one-line hints; free tier excluded — external clients get HTTP 403) while the OpenRouter branch reuses one live `/api/v1/models` fetch and the AWS Bedrock branch reads a committed static allowlist of the 3 account-verified `global.*` inference profiles (`features/admin/model/bedrockCatalog.ts`, live-Converse-verified 2026-11-15 on account 229446390715, region ap-southeast-1 — Nova 2 Lite $0.41/$3.39, Kimi K3 $3/$15, Kimi K3.1 $4/$20 with the reasoning maxTokens ≥16 note); Apply calls `setAgentConfigFn` → `PUT /api/settings/agent-models` (backend writes `agent.provider` / legacy `agent.model` / `agent.models` in one transaction; the legacy `PUT /api/settings/agent-model` route is kept for back-compat and for the box to run against either web version); agent resolution order is backend `agent.models[profile]` → backend `agent.model` → `SKY_AGENT_MODEL` → provider-specific env (`SKY_OPENCODE_MODEL` / `SKY_OPENROUTER_MODEL` / `SKY_BEDROCK_MODEL`) → provider default (`opencode-go` → `deepseek-v4.1-flash`, `openrouter` → `thinkingmachines/inkling-2-small:free`, `amazon-bedrock` → `global.amazon.nova-2-lite-v1:0`; Bedrock baseUrl pinned to ap-southeast-1 via `SKY_BEDROCK_BASE_URL` or default); a second panel clears every astronaut claim for demo housekeeping through `resetClaimsFn` → `POST /api/claims/reset` (backend endpoint carries no auth by design and is loopback-only, so the admin cookie is the only gate; the backend body is never echoed and the page does not refresh the roster afterwards); a third panel — "API Keys" (2026-11-16 merge; `ApiKeysTab.tsx`, icon KeyRound) — folds the OpenCode Go, AWS Bedrock and ElevenLabs key panels into one tab, same write-only anatomy (icon + title + status pill · password field · Save + 2-step Clear confirm · footnote), one section card each: OpenCode Go (`opencode-key.functions.ts` → `saveOpenCodeKeyFn`/`clearOpenCodeKeyFn`/`getOpenCodeKeyInfoFn` → `var/sky-opencode.json`, printable ASCII 8–512, env `SKY_OPENCODE_API_KEY` ?? `OPENCODE_API_KEY` wins, `NSAC_OPENCODE_KEY_PATH` override), AWS Bedrock (new 2026-11-16: `bedrock-key.functions.ts` → `saveBedrockKeyFn`/`clearBedrockKeyFn`/`getBedrockKeyInfoFn` → `var/sky-bedrock.json` mode 0600 gitignored, `NSAC_BEDROCK_KEY_PATH` override, printable ASCII 8–4096 — `aws login` JWT-scale tokens — env `AWS_BEARER_TOKEN_BEDROCK` wins), and ElevenLabs (`elevenlabs.functions.ts` → backend SQLite as before). The Bedrock panel shows a read-only region line (`ap-southeast-1`, override on the host with `SKY_BEDROCK_BASE_URL`) and points at the Models tab to switch provider; the region is deliberately NOT configurable in the UI. Neither file store is ever read back — GET payloads carry only `source` (`env`|`file`|`none`) and `updatedAt`, inputs clear after save, nothing is echoed; env wins over the stored key/token and cannot be cleared from the panel (the hint says so); Sky's agent runtime reads both lazily per session (`readBedrockKey()` env → file now, `bedrockKeySource()` in /health shows env|stored token|missing), so no restart is needed after saving. Every mutating action shares one busy state across the panel and refreshes the status queries after a mutation; `onSessionExpired` bounces back to the unlock form.
