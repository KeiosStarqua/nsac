## Purpose

Full-screen cinematic 3D viewer for `/spacecraft`: renders the NASA ISS adrift in a deep-black universe — Webb "Cosmic Cliffs" backdrop, twin sparse star layers, blue/violet nebula tints, rim/split lighting. The lightweight overview (ISS-B) paints first; the full-detail station streams in around the camera and crossfades in (see `features/iss/AGENTS.md`). Display only — nothing here is measured, and no real crew data is involved. The station carries one **simulated** layer: an illustrative crew-position fixture, six fictional crew members shown as glowing portrait markers (their `public/astronauts/<id>.png` art, initials if it fails) walking a closed patrol loop through the connected modules, standing still at each waypoint (fixture data in `model/crew-positions.ts`; the overlay caption says `POSITIONS SIMULATED`). Exactly one piece of chrome: the crew presence avatar group in the bottom-left (who is checked in); no other chrome.

Served locally; sources in `public/models/iss/SOURCES.md`. The default data path is the streaming one (see Local Contracts); the catalog path (`SPACECRAFT_MODELS` / `DEFAULT_MODEL_ID`) is unchanged for the one-shot fallback.
- Backdrop asset: `public/spacecraft/cosmic-cliffs-web.jpg` (JWST Cosmic Cliffs, NASA/ESA/CSA/STScI, 3840×2224, darkened to 40%), credit in `public/spacecraft/SOURCES.md`. Rendered at opacity ≈ 0.24 behind the canvas over a deep-black base with blue/violet radial tints and a vignette; it must never wash the scene out of "deep black".

## Local Contracts

- **Default data path = streaming** (`features/iss/`): `ISS-B.glb` paints first; parts of the full-detail station stream camera-first behind it; a global ~600 ms opacity crossfade swaps ISS-B for the streamed assembly once the initially-relevant parts are loaded; late parts fade in (~300 ms). `?stream=0` restores the one-shot `ISS-stationary.glb` render (same code path as before); `?part=<id>` (dev-only) streams a single part. `useGLTF.clear(url)` is called on retry after a failed load, for both model URLs. There is no model picker in the DOM.
- Camera framing is the projected-box fit in `model/framing.ts` (pure, vitest-covered): the box's 8 corners are projected onto the view plane perpendicular to the camera direction (`viewBasis`/`projectedExtents`), distance comes from the narrower of the vertical/horizontal half-angles, `padding` 1.18 (≈ 70–85% frame fill) in the scene. Recomputed when the model or the viewport aspect changes; OrbitControls target/min/max distance ride the same framing. (Until 2026-11-14 this was a bounding-sphere fit, which rendered the long truss small.)
- The scene is lazy: `SpacecraftPage` imports `scene/SpacecraftScene` with `lazy()`. The entry chunk must not contain `WebGLRenderer`.
- Starfield: two drei `<Stars/>` layers (140/70 radius, counts 2400/650, saturation 0) inside a group that drifts at ~0.004 rad/s (parallax); `prefers-reduced-motion: reduce` stops the drift and the twinkle (`speed=0`) and disables auto-rotate. The nebula image also stops its slow pan under reduced motion.
- Lighting: dim ambient/hemisphere + cyan-white directional rim from behind-above (intensity 2.4), violet front fill, blue underlight, cool point accent; `RoomEnvironment` PMREM at intensity 0.38 keeps PBR metals readable. There is no bloom post pass — `@react-three/postprocessing` is not a dependency and none may be added; the "bloom" is a radial-gradient halo (a `[background:radial-gradient(…)]` utility on an `aria-hidden` layer) behind the transparent canvas. Canvas is transparent (`alpha: true`, clear color 0 alpha); the cosmic-cliffs backdrop and tints live in CSS layers behind it.
- Chrome: one exception only, the crew presence overlay (see Local Contracts). No title, credit block, toggles, or panels. Loading feedback is a bare `NN%` in the bottom-right corner at low opacity: in stream mode it reflects % of streamed bytes (from the manifest) and disappears when the detail swap completes; `?stream=0` keeps the `useProgress`-based percent. A failed stream shows a one-line banner bottom-left with a `Retry` text button (re-fetches manifest + failed parts); a failed one-shot load (or no WebGL) is caught by `scene/SceneBoundary` and shows a minimal "Spacecraft unavailable" with a retry button. `Escape` navigates to `/`.
- NASA credit: intentionally not rendered on the page (per product decision 2026-11-14 — no text overlays) — same for the crew overlay, which carries no attribution text. The required attribution stays in `public/spacecraft/SOURCES.md` and `public/models/iss/SOURCES.md`; the beui MIT credit lives in `src/shared/beui/avatar-group.tsx` and `THIRD_PARTY_NOTICES.md`.
- **Crew presence (2026-11-15)** — the single chrome exception, in `components/CrewPresence.tsx` (internal; `index.ts` still exports `SpacecraftPage` only). Bottom-left wrapper `absolute left-5 bottom-5 z-10 flex flex-col gap-2 pointer-events-auto`: a mono caption `CREW ON STATION · {checkedIn}/{crew.length}`, `CREW ON STATION · STATUS UNAVAILABLE` when the backend claims call is unreachable, and a bare `CREW ON STATION` before the first answer (no `0/N` flash), then the beui `AvatarGroup` (`src/shared/beui/avatar-group.tsx`, MIT — see `THIRD_PARTY_NOTICES.md`; `max={6}`, `size="md"`, `label="Crew on station"`).
  - Data: fictional crew only (`ASTRONAUTS` from `features/astronaut`, AI-generated portraits from `public/astronauts/<id>.png` handed to the vendored `Avatar` as `src`, initials if a file fails) plus that feature's `getOrCreateSessionId` + `listClaims` server fn, read once on mount through `components/useCrewClaims.ts` (`useSyncExternalStore` over one module-level snapshot, dropped when the last consumer unmounts); an unreachable backend or a throw is tolerated and only changes the caption. The page and the 3D markers read the same snapshot, so avatars and markers cannot disagree. Nothing here is measured, and nothing here claims or releases a crew member.
  - The caption carries a second static mono line, `POSITIONS SIMULATED`, which is the HKT disclosure for the markers below — it stays whether or not the backend answers.
  - `model/presence.ts` (pure, vitest-covered) maps crew → `mine | taken | free`; `mine` wins over a stale `taken` entry, unknown claim ids are ignored, an empty claim list marks everyone `free`.
  - Member styling never fights the vendored `ring-2 ring-background`: `mine` = `opacity-100 [box-shadow:0_0_0_2px_#5EEAD4]`, `taken` = `opacity-100 [box-shadow:0_0_0_1.5px_rgba(94,234,212,0.35)]`, `free` = `opacity-35 grayscale`. Tooltip is one line: `{name} · {role} — {You (in session) | In session | Not checked in}` (Radix portal, `z-[100]`, `side="top"` `sideOffset={24}` so it clears the caption and the count stays readable while hovering).
- **Crew position markers (2026-11-15)** — `scene/CrewMarkers.tsx`, mounted in `scene/SpacecraftScene.tsx` inside the Canvas but *outside* `Suspense`, so the markers never wait for the streamed model. They are scene content, not chrome: no DOM, no label, no interaction, `raycast = () => null` so the stream loader's click-to-prioritise raycast never hits them.
  - Fixtures live in `model/crew-positions.ts` (pure, vitest-covered): six entries, one per `ASTRONAUTS` member, each a closed 3-waypoint patrol loop through the connected modules — Unity/Destiny → Harmony, MBS-Robotics, Zvezda, Columbus → Harmony, Kibo → Harmony, Tranquility/Cupola — walked at 0.85–1.25 world units/s with a per-waypoint dwell (standing stop) of 3–8 s, staggered by a per-member `phaseOffset`. `crew-positions.test.ts` pins every waypoint inside at least one streamed part AND dense samples along every leg inside the union of the parts (`public/models/iss/streamed/manifest.json`), so a fixture can never walk through empty space.
  - Position maths: deterministic patrol locomotion, no `Math.random()` — the marker walks W0 → W1 → … → Wn-1 → W0 forever; each leg eases in/out (smoothstep) at the fixture's walking speed, and the marker stands at each waypoint for `dwell[i]` seconds, reported as `phase: "walk" | "hold"` from `positionsAt(t)`. A subtle bob (radius ≤ 0.12, y-scaled × 0.6, phases baked into the fixture) keeps a standing marker breathing. `phaseOffset` staggers the crew. `positionsAt(t, { static: true })` returns the anchors untouched in `hold` phase — the scene uses it under `prefers-reduced-motion: reduce`, where the walk, the bob and the `mine` pulse all stop. The `mine` pulse also pauses while the member is `hold`.
  - Look: one emissive sphere plus a camera-facing portrait sprite per member, both `depthTest={false}` / `depthWrite={false}` / `toneMapped={false}` at `renderOrder` 20 so they read through the hull; colours mirror the avatar presence states (`mine` bright `#5EEAD4`, `taken` `#9FD8FF`, `free` dim), and the marker colours come from the same `resolveCrewPresence` snapshot as the avatars. The emissive dot settles to `HOLD_SCALE` (0.72) while the member is standing — motion itself is the walking cue, and the `mine` pulse pauses then.
  - The sprite is a **runtime canvas texture** (`labelTexture`): radial cyan glow + the member's initials drawn first as the fallback, then the same `/astronauts/<id>.png` portrait cover-cropped into a circle (34% of the 256 px canvas) with the presence colour as its rim once the `Image` decodes — a failed load keeps the initials, and a texture disposed mid-download ignores the late callback (`disposed` flag). `SRGBColorSpace`; disposed when the marker set changes or unmounts. Never drei's `<Text>`/`<Html>`: `<Text>` fetches a font over the network, `<Html>` renders DOM chrome inside the canvas.
- Auto-rotate stays on by default at 0.35 speed (cinematic drift), pauses on hidden tab, and is disabled under `prefers-reduced-motion: reduce`.
- Styling is Tailwind v4 utilities in `className` (migrated 2026-11-14; `SpacecraftPage.module.css` and `scene/SpacecraftScene.module.css` are gone) on the tokens in `src/styles/global.css`, referenced as `text-(--text)`, `text-(--muted)/85`, `rounded-[999px]`, `font-(family-name:--mono)`. The one stylesheet left is `nebula-drift.css`: it holds only `@keyframes nebulaDrift`, because a keyframe cannot be a utility — the element carries `animate-[nebulaDrift_110s_ease-in-out_infinite_alternate]` and `motion-reduce:animate-none`.
- The app reset in `src/styles/global.css` is **unlayered**, so it outranks the layered utilities; utilities whose property that reset also declares on the same element carry the `!` suffix (`text-[10px]!` on a `<button>`, `rounded-[999px]!` where `:focus-visible` would flatten the pill). No i18n — same as `features/body-map/`.

## Work Guidance

- New models go into `SPACECRAFT_MODELS` in `model/models.ts` (keep it pure); draco-required models must use the local `DRACO_DECODER_PATH`.
- Scene behaviour belongs in `scene/`; keep `model/` free of React, three.js and DOM.
- Do not add UI panels, controls, or text overlays to this route; if feedback is needed, keep it to the bare-percent pattern. The crew presence group is the one exception — extend it rather than adding a second overlay.
- Crew presence styling is utilities only, on the same tokens as the page (`text-(--muted)/85`, `font-(family-name:--mono)`, arbitrary `[box-shadow:…]`); keep the caption a single line so it survives at ≤480px, and keep the group's member list abbreviated to `{id, name, hint, className}` for the vendored component.
- The crew markers stay chrome-free and fixture-only: scene content (`scene/CrewMarkers.tsx`), so no DOM node, no names or module labels, no toggles, no pointer handlers, nothing to hover. Waypoint or loop changes go into `model/crew-positions.ts` (its test pins every waypoint into the streamed manifest bounds AND dense samples along every leg inside the union of the parts); colour comes from the shared claims snapshot, never from a local guess. Sprite scale/offset/texture size are constants in the component (the station spans x ∈ [-56, 56] world units) and any canvas texture created there is disposed on unmount.
- Keep `public/spacecraft/SOURCES.md` credit intact if the backdrop asset changes.
- Chrome styling is utilities only: no `@apply`, and no new CSS files beyond `nebula-drift.css` (keyframes only). Check a styling change by dumping `getComputedStyle` (and `getBoundingClientRect`) per element before and after, at 1672×941 and 390×844; the 3D canvas and the starfield are not deterministic enough to diff.
