# features/iss

## Purpose

Streamed (spatial) loading of the NASA ISS full-detail model for `/spacecraft`: the page paints the lightweight overview first, then streams the parts of the full-detail station around the camera instead of loading one 42.4 MB GLB. Display only — no simulation, no data claims, no UI chrome.

## Ownership

- Owns everything under `features/iss/`. `index.ts` is the public surface: `ISSStreamer`, `ISSFramingBox`, `ISSStreamStats`, `loadISSManifest`, `getISSManifest`, `getISSPartLoader`, types (`ISSStreamManifest`, `ISSStreamPart`).
- `SpacecraftScene.tsx` (in `features/spacecraft/`) mounts `<ISSStreamer/>` instead of the one-shot model by default — the one sanctioned feature→feature import (both features live on `/spacecraft`). `~/features/iss` resolves via tsconfig paths.
- The streamed assets are generated by `scripts/iss/split-iss.ts` (+ `verify-iss.ts`) and live in `apps/web/public/models/iss/streamed/` (parts + `manifest.json` as text; `.bin`/`.png`/`.jpg` in Git LFS, rules in root `.gitattributes`). `ISS-stationary.glb` and `ISS-B.glb` are untouched and remain the `?stream=0` fallback and the overview, respectively.

## Local Contracts

- **Data path (default):** `ISS-B.glb` (466 KB, drei `useGLTF` + local draco decoder) paints first → `manifest.json` is fetched (deduped in-flight) → parts stream through `ISSPartLoader` (concurrency 3, shared textures via `../textures/<sha256>.png` — HTTP-fetched once with `THREE.Cache.enabled`, each part uploads its own GPU textures) → when every **initially-relevant** part is loaded, a global opacity crossfade (~600 ms; instant under reduced motion) swaps ISS-B for the assembled station. Parts arriving after the swap get a ~300 ms fade-in. ISS-B is unmounted at the end of the fade.
- **`?stream=0`** mounts the old one-shot `ISS-stationary.glb` path unchanged (never touches this feature). **`?part=<id>`** (dev-only) force-streams a single part; unknown ids degrade to normal streaming.
- **Relevance (per 250 ms tick):** projected bounding-sphere radius in px (fov 38, `size.height`); stream at ≥ 60 px in-frustum, keep mounted down to ≥ 30 px (hysteresis). Below KEEP a mounted part unloads; it reloads from `THREE.Cache` on return (no network). Priority = pixel radius; clicks on a part boost it to the front of the queue (raycast, `userData.partId`). Queued-but-irrelevant parts are cancelled before they start. Camera-driven; no requests fire for unchanged camera between ticks (epsilon via the 250 ms interval).
- **LRU:** `ISSPartLoader` keeps at most 6 unpinned loaded parts; pinned parts (currently visible/mounted) are never evicted. Eviction (geometry/material/texture dispose) happens only in `unpin()` — never at load completion, so a fresh part cannot be disposed before React pins it. GPU-visible parts are not capped; the cap applies to hidden cache.
- **Bounds in the manifest are real** (accessor POSITION min/max + world matrices, verified against the source GLB by `verify-iss.ts`). `bytes` per part = on-the-wire cost with shared textures counted at the first part that references them; sum = true total (~32.5 MB at this writing, vs 42.4 MB one-shot).
- **Failures never blank the page:** manifest fetch fails → overview stays + light banner ("Detail stream unavailable — overview only"); a part fails → crossfade deferred, ISS-B stays + banner + retry (re-fetches manifest too); late part failure in detail mode → banner only. No crash path (SceneBoundary still covers the canvas).
- **Stats:** `onStats({ loadedBytes, totalBytes, loadedCount, totalCount, phase, error })` — `phase: "overview" | "crossfading" | "detail"`. Host renders the bare `NN%` (hides at `detail`) and the error banner outside the Canvas.
- three.js stays out of the HUD entry chunk: the feature is only imported through `~/features/iss` from the lazily-loaded `SpacecraftScene`.

## Work Guidance

- Regenerate streamed assets only with `bun scripts/iss/split-iss.ts` (then `bun scripts/iss/verify-iss.ts`); never hand-edit `streamed/`. LFS storage for the streamed binaries is required — never commit them as plain git objects.
- Keep `loaderTick`-based React subscriptions honest: anything the UI shows from the loader must flow through `notify()` → `subscribe()`.
- New part kinds extend `PARTS` in `split-iss.ts` (node indices, not names) — coverage must stay 131/131 mesh nodes with zero overlap (asserted by the script).
- No UI chrome may be added here; feedback rides the shared bare-percent/banner pattern owned by `features/spacecraft`.

## Verification

- `bun run typecheck` (after `bun run build` so `routeTree.gen` exists), `bun run test` (web). `iss-relevance.test.ts` covers the pure maths.
- Headless Chromium + CDP (`scripts/iss/bench-iss.ts`): cold load → ISS first visible (~0.5–1 MB model bytes), all parts loaded (~31 MB streamed, ~2.7 MB page, ~46 requests), zoom in/out (0 new bytes), console errors = 0 (except the known `THREE.Clock` deprecation).
- Visual: overview (ISS-B) → crossfade → full detail; zoom drill-down stays cached; `?stream=0` matches the pre-streaming behaviour.
