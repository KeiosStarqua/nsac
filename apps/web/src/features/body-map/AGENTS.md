## Purpose

The body hologram around the Open Anatomy 3D male model, in two variants. `variant="overlay"` (the default) is the HUD's full-screen glass panel: header, `LayerRail`, `StructureCard`, CC BY 4.0 footer. Keep that render unchanged — it is the HUD modal; today the HUD's `#hologramButton` is a `<Link to="/body">`, so no route mounts the overlay variant. `variant="page"` is the `/body` route (`BodyMapPage`): fullscreen with no chrome — the canvas at `absolute inset-0` (`role="img"` + `aria-label`; the 3D is not itself a screen-reader surface), the floating "Body systems" rail, one attribution line, one discreet kbd chip (`Esc` · `HUD`) that calls the same `onClose` as `Escape` → HUD, the accessible Body Tree (`components/BodyTree.tsx`; a left-edge toggle + drawer listing all 147 catalog structures, grouped by system, keyboard/SR selectable) and a non-drag `ViewControls` pill (rotate/zoom/Reset View — DESIGN.md BodyVolume rule). In both variants a click on a structure picks its catalog key and eases the camera to it, and hovering (or tapping on a touch screen) shows that structure's catalog facts in a small card at the pointer; the overlay variant additionally shows its catalog facts and — for the heart, lungs and brain — the simulated HUD readings. Showcase only; nothing is measured or diagnosed.

## Ownership

- Owns everything under `features/body-map/`. `index.ts` is the public surface: `BodyMapOverlay` + `BodyMapOverlayProps` and `BodyMapPage`.
- `components/BodyTree.tsx` (2026-11-15): the page variant's accessible Body Tree — a pure-`model/tree.ts`-backed toggle + drawer listing the catalog; page variant only, the overlay variant renders neither.
- `components/ViewControls.tsx` (2026-11-15): the page variant's drag-free camera — DOM buttons for rotate left/right, zoom in/out and `Reset view` (`Focus` icon); page variant only, rendered only when WebGL is available.
- Code outside the feature that belongs to it: `routes/body.tsx` (renders `<BodyMapPage />`, the page variant), the `#hologramButton` links to `/body` in `features/hud-gen/catalog.tsx`, and the HUD health card's minimal 3D scene (`features/sky-hud/components/HoloScene.tsx`, rendered on the `/` console) which imports `model/materials.ts`, `model/layers.ts` and `model/framing.ts` — those three modules are the contract, they stay pure and table-driven.
- The model asset is `apps/web/public/models/anatomy-male.glb` (~6,250,000 bytes after meshopt simplify), served locally. Never point at the package CDN. The HUD cards' subset is `apps/web/public/models/anatomy-male-holo.glb` (skin + skeleton, 29 meshes, 124,566 tris, ~876 KB, meshopt) generated by `bun scripts/holo-model.ts`; regenerate it there, never by hand. The generation script bakes the pubis flatten into that file (same `flattenPubis`/`PUBIS_REGION` tables, applied after dequantize + baking the skin node transform, then smooth normals + meshopt): the card has no runtime flatten, `anatomy-male.glb` stays byte-identical, and the runtime `/body` path is still the one that flattens `anatomy-male.glb` on load.

## Local Contracts

- `variant` selects the chrome, never the scene: `"overlay"` renders header + `StructureCard` + footer cards around the canvas; `"page"` (`/body` only) renders no header, no `StructureCard`, no footer — its one piece of chrome is `components/EscapeChip.tsx`, a discreet kbd chip (`Esc` · `HUD`, fixed English copy) in a `<button type="button" aria-label="Back to HUD (Escape)">`: desktop `bottom-[10px] right-[14px]` (the attribution owns bottom-left), `top-[12px] right-[12px]` under 900px (the loading pill owns top-left there and the rail becomes a bottom row), `z-10`, `pointer-events` auto; activating it calls the same `close` → `onClose` the Escape handler uses (the component is hook-free so vitest can activate it without a DOM) — `role="main"` with an `sr-only` `<h1>` ("Body hologram"), the canvas wrapper at `absolute inset-0` with `rounded-none border-0` and the same `#050c16` radial, `LayerRail` floating (right `clamp(14px,2vw,28px)`, `top-1/2`/`-translate-y-1/2`, z-10; a bottom row under 900px), and one `text-[12px]` dim line carrying `ATTRIBUTION` + the CC BY 4.0 link (bottom-left on desktop; top-left under 900px at `top-[46px]` so the bottom rail cannot cover it and the loading pill owns the very top). `BodyScene` takes `progressPlacement?: "bottomLeft" | "top"` (default `"bottomLeft"`, the overlay card's free corner); the page passes `"top"` — the pill sits top-right (top-left under 900px, above the attribution line) so it never overlaps the page's attribution or rail. `selected` still reaches `BodyScene`, so a click still eases the camera; `Escape` goes through `onClose` → `navigate({ to: "/" })` in both variants — on the page variant the Body Tree drawer closes first (Escape no longer navigates away with the drawer open; the drawer is the dialog's inner layer). The attribution line is `text-[12px]` (the page's caption floor), `opacity-[0.9]`; the Escape chip `text-[11px]`.
- Layer state is `LayerMap = Record<AnatomySystem, boolean>` (`model/layers.ts`), all seven catalog systems including `joints` (hotspot markers, not meshes). `LayerRail` receives `layers` and a `Dispatch<SetStateAction<LayerMap>>`; the last visible layer cannot be switched off. Toggle buttons carry `min-h-[44px]` (Sky touch target); the off state uses `opacity-[0.75]` so switch-off labels stay ≥4.5:1. `LayerRail`'s copy and styling are fixed — the page variant only positions the component.
- Mesh names and catalog keys are the same except the skin: the GLB names it `skin_1`, the catalog key is `skin`. Use `structureKeyForMesh` / `meshNameForStructure`; never compare names directly.
- Genitalia are handled at runtime in `model/genitalia.ts` (pure, table-driven), never in the asset: `HIDDEN_GENITALIA_MESHES` + `shouldHidePenis` keep `reproductive` — the asset's one mesh for the whole male tract (ducts, seminal vesicles, penis corpora/glans, testes) — invisible even when the Organs layer is on, and `PUBIS_REGION` + `flattenPubis`/`isPubisMesh` press the skin's sculpted genital bulge back onto the pubic plane (measured on the real GLB: bulge reaches z 0.1049 against a pubic plane at ~0.045, flattened to ~0.06) on a float32 copy of the `skin`/`skin_1` geometry made at load, because the GLB's POSITION/NORMAL are normalized integer attributes; the cached source geometry stays untouched, the copy is disposed on unmount, nothing is deleted so there is no hole, and the CC BY asset stays byte-identical. Residual: a faint flat-patch crease in the 10 % skin shell, visible only when zoomed to the pelvis.
- Readings come only from `VITAL_VALUES` in `features/sky-hud/vitals.ts`, mapped by structure key in `model/selection.ts`. Do not type a number into prose; the card always says the data is simulated.
- three.js and the scene are lazy: `BodyMapOverlay` imports `scene/BodyScene` with `lazy()`. The entry chunk must not contain `WebGLRenderer`; check the built `assets/index-*.js`.
- Fallbacks: no WebGL → readable message with `ATTRIBUTION`; a failed GLB (meshopt) load is caught by `scene/SceneBoundary` (R3F rethrows canvas errors into the DOM), shown with the same message plus retry. The scene subtree (preparing state, fallbacks, `<BodyScene>`) is built once and shared by both variants. `ATTRIBUTION` stays verbatim next to the CC BY 4.0 link in the overlay footer and in the page variant's attribution line.
- Styling is Tailwind v4 utilities in `className` (migrated 2026-11-14; `BodyMapOverlay.module.css` and `scene/BodyScene.module.css` are gone, no stylesheet left) on the tokens in `src/styles/global.css`, referenced as `bg-(--surface)`, `text-(--muted)`, `border-(--accent)/22`, `rounded-(--radius)`, `font-(family-name:--mono)`. The catalog colour is the one data-driven value and travels as the `--swatch` custom property, read by `[background-color:var(--swatch,var(--accent))]`.
- The app reset in `src/styles/global.css` is **unlayered**, so it outranks the layered utilities; a utility whose property that reset also declares on the same element keeps the pre-migration rendering with the `!` suffix (`text-[13px]!` on a `<button>`, `tracking-[0.01em]!`/`leading-[1.25]!` on an `<h2>`/`<h3>`, `mt-[6px]!` on a `<p>`, `rounded-[999px]!` where `:focus-visible` would flatten it). `hover:text-(--text)!` is needed for the footer link, whose `a:hover` colour is unlayered.
- Camera maths is pure (`model/framing.ts`); `scene/OrganFocus` eases camera position and the OrbitControls target over 600 ms and jumps instantly under `prefers-reduced-motion`.
- Hover/tap tooltip (2026-11-15): `BodyScene` reports the catalog structure under the pointer through the optional `onHover` prop, and both variants render `components/HoverTooltip.tsx` — a `pointer-events-none`, `position: fixed` card that follows the pointer (14 px right/below, flipped at the viewport edge and clamped inside it), `z-20` (shared with the Body Tree drawer) so it sits above the canvas and the `z-10` rail without taking a click from either. Content is catalog facts only — `structure.label`, `SYSTEM_LABELS[system] · category`, the structure's colour as `--swatch` — never a reading or a claim, so it needs no source. The pick is the click's own rule, shared as `pickStructureKey` (`model/hover.ts`): hidden meshes are skipped (a switched-off layer, the genitalia meshes), the skin comes last because the 10 % shell is in front of everything, and a mesh outside the catalog yields no tooltip. Reporting is throttled (`shouldReportHover`: a new key or a ≥ 6 px step) so a pointer move does not re-render the model, and `HoverTooltip` measures its own box (`tooltipPlacement`) so the flip is exact. Touch never hovers: `pointermove` with `pointerType: "touch"` is ignored during an orbit, and a `pointerup` within 4 px (the click's own drag guard) pins the card where the finger landed, until the next touch, a tap on empty space (`onPointerMissed`) or a new drag. Click-to-select, the camera ease and `Escape` are unchanged.
- Body Tree (2026-11-15): the `page` variant only also renders `components/BodyTree.tsx` — closed, render ONLY a left-edge toggle (`absolute left-[clamp(14px,2vw,28px)] top-1/2 -translate-y-1/2 z-20`, round icon button, `aria-expanded="false"`, `aria-label="Open body tree"`); open, a drawer (`absolute inset-y-0 left-0 z-20 w-[min(82vw,300px)]`, panel on `#050c16` with `backdrop-blur`, transform-only slide-in, no transition under `motion-reduce`) whose header carries the "Body Tree" eyebrow and a close button (`aria-label="Close body tree"`, same round-button style) and whose `<nav aria-label="Body tree">` lists the full catalog grouped by system — one `<section>` per system, `<h3>` mono-caps eyebrow with the system label and item count, rows as `<button type="button" aria-pressed>` (swatch dot via `--swatch`, label, truncated secondary category). Grouping is pure (`model/tree.ts`; systems in `SYSTEMS` order, catalog order stable, all 147 keys, female-only structures included); rows flag `simulated` — a tiny `SIM` badge — iff the key is in `VITALS_BY_KEY` (heart, lung_l, lung_r, brain). Selection is the canvas's own `selected` state passed straight through (`onSelect={setSelected}`), so a row click eases the camera like a 3D pick (and a 3D pick lights up the row); the tree holds no selection state of its own. `Escape` with the drawer open closes the drawer only — the page close (→ HUD) is the next Escape (`treeOpen` participates in the page variant's keydown); the overlay variant has no drawer and `Escape` still closes on the first press. Copy is fixed English. The overlay variant renders neither piece.
- ViewControls (2026-11-15, page variant only, and only when WebGL is available): `components/ViewControls.tsx` — the non-drag camera DESIGN.md requires (BodyVolume §15.2: rotate/zoom buttons + Reset View). A `role="group"` pill (`aria-label="View controls"`) with five 44px buttons (`RotateCcw` "Rotate body left", `RotateCw` "Rotate body right", `ZoomIn`, `ZoomOut`, `Focus` "Reset view"), fixed English copy; `top-[12px]` centered over the canvas on desktop (the loading pill owns top-right), flipped to a vertical right-edge stack at ≤900px (the Body Tree toggle owns the left edge there). The actions reach the canvas through an imperative bridge: `BodyScene` mounts `ViewBridge` inside `<Canvas>` when the page passes `viewRef` — it reads `camera` + `useThree(state => state.controls)` (makeDefault OrbitControls), rotates by a fixed 22.5° azimuth step around the target, clamps zoom to the controls' `minDistance`/`maxDistance`, and `Reset view` restores `DEFAULT_CAMERA`/`DEFAULT_TARGET` and clears the selection (`OrganFocus` then eases back to the whole-body framing). The HUD overlay passes no `viewRef`, so no bridge and no buttons are mounted there.

## Work Guidance
